# 成片生产检查表

## A. 立项

- [ ] 已在素材管理器和 `src/packs/` 里检索过现成风格、组件和动效。
- [ ] 一句话说清楚：这条视频让观众记住什么？
- [ ] 目标时长和发布平台明确。
- [ ] 视觉方向能用 3 个关键词描述。
- [ ] 至少确定一个重复出现的系列识别元素。

## B. 脚本

- [ ] 开头 3 秒有钩子。
- [ ] 每 10–15 秒有一个信息转折。
- [ ] 每个概念有一个具体例子。
- [ ] 旁白按呼吸拆句，单句不超过约 36 个汉字。
- [ ] 每句最多 2 个关键词高亮。
- [ ] 结论不是重复标题，而是给观众一个可带走的判断。

## C. 分镜

- [ ] 每个镜头有视觉动作：揭示、对比、计数、拆分、盖章、连接、转化。
- [ ] 不存在“只有一段字”的空镜头。
- [ ] 章节边界有明确转场。
- [ ] 重点数字有落点，关键结论有停留。
- [ ] 片尾至少留 3–4 秒给结论卡和品牌标识。

## D. 版式

- [ ] 左右安全区 86px，底部字幕安全区 34px。
- [ ] 主标题字号 64–136px，正文不小于 18px。
- [ ] 同一画面不超过 3 个主色。
- [ ] 同一画面只有一种阴影语言。
- [ ] 卡片、贴纸、印章没有互相遮挡信息。
- [ ] 长句字幕已完成抽帧检查。
- [ ] 手机尺寸缩略后，标题仍能在 2 秒内读懂。

## E. 动效

- [ ] 所有动画由 frame/spring/interpolate 驱动。
- [ ] 没有 CSS transition 或依赖真实时间的动画。
- [ ] 同一屏最多两个焦点同时运动。
- [ ] 入场动作有延迟层级，不是所有元素同时弹出。
- [ ] 转场没有连续重复使用同一种形式。
- [ ] 关键停顿没有被过度动画填满。

## F. 声音

- [ ] 旁白逐句对齐，没有拖拍或截断。
- [ ] BGM 在所有旁白区间自动 duck。
- [ ] 转场音效不高于旁白。
- [ ] 同屏最多一个主要音效。
- [ ] 关键数字/结论有声音确认，但不堆叠。
- [ ] 结尾 BGM 有收束或淡出。

## G. 质检帧

至少检查以下位置：

- [ ] 第一屏和章节标题
- [ ] 最长字幕句
- [ ] 数字最多的画面
- [ ] 深色/浅色切换处
- [ ] 卡片和贴纸边缘
- [ ] 结尾公式卡
- [ ] 最后一帧

## H. 三层预览门禁

改完场景不要直接整片渲染。按下面三层依次过，上一层不通过不进入下一层。

```bash
# 1. 关键帧：改一段只看 3–4 帧，约 15–40 秒
npm run preview:shots -- --project <id|path> --section review

# 2. 段落视频：确认动效、转场和音画同步，约 30–90 秒
npm run preview:section -- --project <id|path> --section review --draft

# 3. 整片：前两层通过后再跑完整流水线
npm run pipeline -- --project <id|path>
```

- [ ] 关键帧无叠字、残影、空镜、元素越界。
- [ ] 正文最小字号 ≥ 36px，单帧文本块 ≤ 10。
- [ ] 无 `REC`、页码、录制时长等无关英文。
- [ ] 画廊 `local/preview/<id>/index.html` 已逐段看过。
- [ ] 只改了某段时，没有重渲整片。
- [ ] `npm run check:composition -- --project <id|path>` 无阻塞项。

## I. 技术验收

```bash
npm run check
npm run check:timeline -- --project <id|path>
npm run pipeline -- --project <id|path>
```

- [ ] `video.project.json` 的入口、Composition、输出路径和视频规格正确
- [ ] `video.project.json` 已配置 `cover`，封面 `Still` 为 `1440×1080`（4:3）
- [ ] 时间轴 section 连续，字幕窗口无重叠，旁白文件全部存在
- [ ] 1920×1080
- [ ] 30fps
- [ ] H.264
- [ ] AAC / 48kHz / stereo
- [ ] 帧数 = 时长 × 30
- [ ] 响度约 -16 LUFS（允许 ±1.5）
- [ ] True Peak ≤ -1.0 dBTP
- [ ] 文件可正常播放，开头/中段/结尾均无黑帧或静音异常

## J. 交付

- [ ] 最终文件命名包含 `-final`。
- [ ] 保留流水线生成的 4:3 封面图。
- [ ] 保留可重渲染工程。
- [ ] 中间渲染文件与缓存可清理。
- [ ] 发布前确认字幕在手机端可读。

## K. 沉淀

- [ ] 已列出这次新做的组件、动效、声音和场景结构。
- [ ] 只保留“换文案、换色板、换项目还能用”的资产。
- [ ] 可复用部分已放进 `src/packs/<pack-id>/`，不是复制在私有项目里。
- [ ] `pack.json` 已声明入口、预览 Composition、色板和组件。
- [ ] `src/library/original-packs.json` 已登记 palette、style 和 pack。
- [ ] `src/Composition.tsx` 已注册 10 秒预览 Composition。
- [ ] `docs/ASSET_LIBRARY.md` 已补资产说明。
- [ ] `npm run pack:check` 通过。
- [ ] `npm run check` 通过。
- [ ] `npm run check:boundaries` 确认 `src/` 没有引用私有项目内容。
- [ ] 已抽查预览帧，确认拆包后没有叠层、遮挡或字幕溢出。
- [ ] 具体文案、配音、时间轴、成片和 QC 帧没有进入 `src/packs/`。

## 常见返工原因

1. 先做画面再想脚本，导致节奏被视觉拖着走。
2. 字幕按写作长度设计，没有按真实 TTS 时长设计。
3. 每个镜头都想塞一个海报，结果没有主次。
4. 贴纸、印章、星爆同时出现，焦点过多。
5. 只靠肉眼验收，没有检查峰值、帧数和抽帧。
6. 转场音效比旁白更抢，导致信息听不清。
7. 做完就丢，下一条视频重新造同一套组件和动效。
